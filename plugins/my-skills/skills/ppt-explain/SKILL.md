# ppt-explain — 주제를 PPT 아티팩트로 설명하기

사용자는 무언가를 이해하고 싶을 때 "PPT 아티팩트로 만들어 설명해줘"라고 자주 요청한다.
결과물은 **claude.ai Slides 아티팩트**(16:9, 넘겨보기·.pptx/PDF 다운로드 가능)이며, 로컬 .pptx 파일이 아니다.

## 0. 기본값 (따로 말이 없으면)

| 항목 | 기본값 |
|---|---|
| 언어 | 한국어. 고유명사·API·명령어·코드 식별자는 원문 영어 유지 |
| 분량 | 8–12장 (가벼운 주제 6–8장, 깊은 기술 주제 최대 15장) |
| 청중 | 개발자인 사용자 본인. 기초 용어 설명은 짧게, "어떻게 동작하나"에 무게 |
| 디자인 시스템 | 계정에 없음 → 없이 진행 (사용자가 지정하면 그것 사용) |
| 출력 | Slides 아티팩트 1개 + 채팅에는 링크와 3–5줄 요약 |

질문은 최소화한다. 대상이 모호할 때만(예: 같은 이름의 기능이 여럿) 한 번 묻고, 그 외에는 합리적으로 판단해 바로 진행한다.

## 1. 조사 — 사실부터 확보

덱을 만들기 전에 주제를 1차 자료로 확인한다. 기억에 의존해 쓰지 않는다.

- **GitHub 저장소**: scratchpad 디렉터리에 `git clone --depth 1` → README, 아키텍처 문서(CONCEPTS/ARCHITECTURE/docs), 디렉터리 구조, 핵심 엔트리포인트를 읽는다. 저장소 안의 다이어그램 이미지가 있으면 확인한다. 클론한 코드는 실행하지 않는다.
- **최신 기능·뉴스·제품**: WebSearch(standard 우선, 결과가 빈약하면 extended). 공식 출처(공식 블로그, changelog, 문서)로 날짜·명칭을 교차 확인한다. 이름이 정확히 일치하지 않으면 가장 가까운 후보를 찾고 덱과 답변에 그 사실을 밝힌다.
- **로컬 코드/내 작업**: 해당 파일을 직접 읽는다. 필요하면 claude-mem 검색으로 과거 맥락을 가져온다.
- 확인 못 한 내용(출시일, 수치, 로드맵 등)은 지어내지 말고 "미확인" / "프리뷰 단계" 등으로 표시한다.
- 조사 범위가 넓으면(파일 여러 개를 훑어야 하는 경우) Explore/general-purpose 에이전트에 위임해 결론만 받아도 된다.

## 2. 스토리 설계 — 덱 구성

조사 결과를 아래 골격에 맞춰 슬라이드별 한 줄 메시지로 먼저 정리한다. 주제에 맞게 빼거나 합친다.

1. **표지** — 제목 + 한 줄 부제(무엇을 한 문장으로) + 날짜/출처 유형
2. **한 줄 요약 / TL;DR** — 이것이 무엇이고 왜 중요한가 (3개 이내 핵심 포인트)
3. **문제·배경** — 기존 방식의 한계, 왜 나왔나
4. **핵심 개념** — 꼭 알아야 할 용어 2–4개
5. **동작 원리 / 아키텍처** — 다이어그램(흐름도·계층도·시퀀스) 중심. 덱의 핵심 슬라이드
6. **상세 흐름** — 단계별(1→2→3) 또는 요청 한 번의 생명주기
7. **사용법 / 예시** — 설치·명령어·코드 스니펫·화면 흐름
8. **비교** — 대안·이전 버전과의 표 비교 (해당될 때)
9. **한계·주의점·현재 상태** — 프리뷰 여부, 알려진 제약, gotcha
10. **정리 + 다음 행동** — 3줄 요약, 써볼 만한 경우/아닌 경우
11. **출처** — 참고한 URL·파일 목록

슬라이드 작성 원칙:
- 슬라이드마다 **제목 = 그 장의 결론 문장** ("아키텍처" 대신 "모든 요청은 Core를 거쳐 OS별 어댑터로 간다").
- 본문은 불릿 3–5개, 한 불릿 한 줄 내외. 문단 금지.
- 메커니즘은 글보다 그림으로: 흐름·계층·상태 전이는 다이어그램, 수치 비교는 표/차트.
  다이어그램을 그릴 때는 `artifact-diagramming` 스킬, 차트는 `dataviz` 스킬을 먼저 로드한다.
- 코드 스니펫은 짧게(10줄 이내), 핵심 줄만.
- 슬라이드 간 용어를 통일한다.

## 3. 아티팩트 생성 — Slides 타입

1. `Artifact` 도구 `action: "quickstart"`, `intent: "slides"` 를 호출한다 (새 덱마다 1회).
   - 참고: 현재 Slides 타입 URL은 `https://claude.ai/artifact/8jTsAFQMFDb2oA8MsPJ2eL` 이지만, 항상 quickstart 결과의 값을 우선한다.
2. quickstart 안내대로 `type_url`, `title`(짧은 한국어 제목), 파일 없이, `auto_open: "after_first_write"` 로 publish 해 새 아티팩트를 만든다.
3. 생성 결과에 담긴 **타입 지침과 "먼저 읽을 페이지"를 그대로 따른다** (데이터 파일 형식, 슬라이드 레이아웃, 채우는 방법은 거기에 있다). 이 스킬의 내용과 충돌하면 타입 지침이 우선.
4. 2단계에서 설계한 구성으로 내용을 채워 같은 `url`에 publish 한다.
5. 다 채운 뒤 결과를 확인한다(타입이 제공하는 확인 수단이 있으면 사용). 브라우저로 직접 확인이 필요하면 `ego-browser` 스킬을 쓴다.

주의:
- 사용자가 .pptx 파일 자체를 요구하지 않는 한 pptx/genoffice 스킬로 로컬 파일을 만들지 않는다. Slides 아티팩트는 자체적으로 .pptx/PDF 다운로드가 된다.
- 실존 회사·제품의 로고/브랜딩을 흉내 낸 디자인은 쓰지 않는다. 이름과 사실 언급은 괜찮다.

## 4. 마무리 응답

채팅 답변은 짧게:
- 덱 링크
- 3–5줄 핵심 요약 (덱을 안 열어도 요지를 알 수 있게)
- 조사 중 발견한 불확실성·이름 불일치가 있으면 한 줄로 명시
- 덱 전체 내용을 채팅에 다시 옮겨 적지 않는다

claude-mem `work_state_write` 사용 가능 시 해당 작업 항목에 `work_product`로 덱 URL을 첨부한다.

## 5. 수정 요청이 올 때

- 같은 대화에서 만든 덱: 같은 `url`로 다시 publish 해 링크를 유지한다.
- 이전 대화의 덱: `action: "list"`(필요하면 `type: "Slides"`)로 찾아 `action: "read"` 후 그 버전을 기반으로 수정해 같은 `url`에 publish.
- "더 자세히", "슬라이드 추가" 요청은 기존 흐름 안에 끼워 넣고, 표지·요약·출처 슬라이드도 함께 갱신한다.
